# Publishing Module — Master Spec

## Goal

Extend Horizon with a dedicated publishing pipeline that takes blog posts generated by `horizon-blog` and publishes them as draft CMS items to Webflow, with deduplication to avoid re-publishing articles already in the collection.

## Pipeline Position

```
uv run horizon          → fetch & score news items
uv run horizon-blog     → generate markdown blog posts
uv run horizon-publish  → deduplicate & push drafts to Webflow
```

Each step is a separate CLI command and can be run independently.

## Module Structure

All publishing logic lives under `src/blog/` alongside the generator, sharing common models and profiles:

```
src/blog/
  models.py            ← shared: BlogPost, BlogConfig, ScoredItem, etc.
  profiles/            ← shared: prompt profiles
  generator/           ← all current blog generation files (moved from src/blog/)
    __init__.py
    runner.py
    writer.py
    scorer.py
    enricher.py
    fetcher.py
    loader.py
    reporter.py
    prompts.py
  publisher/           ← new publishing module
    __init__.py
    publisher.py       ← abstract Publisher base class
    webflow.py         ← WebflowPublisher implementation
    runner.py          ← horizon-publish CLI entry point
```

## Abstract Publisher Interface

The `Publisher` base class defines the contract all CMS implementations must satisfy:

- `add_draft(item)` — create a draft item in the collection
- `list_items(since=None)` — list collection items, optionally filtered by date
- `get_item(item_id)` — retrieve a single item by ID
- `publish_draft(item)` — promote a draft to live
- `delete_item(item_id)` — remove an item from the collection

## Webflow Implementation

Provider: [Webflow CMS API](https://developers.webflow.com/data/reference/cms/collection-items/staged-items/)

Configuration:
- `WEBFLOW_TOKEN` — environment variable (API token)
- `collection_id` — in `data/config.json` under `blog.publisher`

Field mapping for Webflow CMS items:
```json
{
  "fieldData": {
    "name": "<title>",
    "slug": "<url-safe slug>",
    "meta-title": "<SEO title>",
    "meta-description": "<SEO description>",
    "content": "<rich HTML>",
    "published-date": "<ISO 8601>",
    "min-read": "<N min read>",
    "featured-on-top": "false"
  },
  "isArchived": false,
  "isDraft": true
}
```

## Deduplication

- Time window: configurable `deduplication_time_window` (default: 2 weeks)
- Fetch all Webflow collection items created/published within the window
- Match against generated blog posts by **title** (exact or normalised string match)
- Items already present in draft or published state are filtered out
- More sophisticated matching (URL, semantic similarity) deferred to a future phase

## Markdown → HTML Conversion

Use `markdown` (Python-Markdown) — the standard, most widely adopted library. No custom renderer needed for Phase 1.

## Phases

### Phase 1 — Module Scaffold
- Move all current `src/blog/*.py` files into `src/blog/generator/`
- Keep `models.py` and `profiles/` at `src/blog/` level (shared)
- Create `src/blog/publisher/` with abstract `Publisher` class and `WebflowPublisher` implementation
- Wire up `horizon-publish` CLI entry point (reads generated posts, stubs dedup/push)
- Add `collection_id` and `deduplication_time_window` to `BlogConfig`

### Phase 2 — Deduplication
- Implement `WebflowPublisher.list_items(since)` against the Webflow API
- Fetch items within the dedup time window
- Filter generated posts by title match against existing Webflow items
- Log which items were filtered and why

### Phase 3 — Push as Drafts
- Convert markdown blog posts to rich HTML using Python-Markdown
- Generate SEO title and meta description via AI
- Compute reading time estimate from character count
- Call `WebflowPublisher.add_draft()` for each surviving item
- Log results (created / skipped / failed)

## Non-Goals

- Scheduling or automatic publishing of drafts (manual review in Webflow before going live)
- Support for CMS providers other than Webflow in the initial build
- Editing or updating already-published items
- Semantic/embedding-based deduplication (deferred)
